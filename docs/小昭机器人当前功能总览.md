# 小昭招聘机器人2.2当前功能总览

整理时间：2026-06-11

本文按“能做什么”重新整理小昭招聘机器人 2.2 的当前功能。详细执行规则以 `skills/xiaozhao-robot-2/SKILL.md` 和 `docs/小昭机器人2.0说明.md` 为准。

## 1. BOSS/Zhipin 候选人筛选

小昭可以执行当前 BOSS/Zhipin 推荐牛人筛选流程：

- 读取 `职位管理 -> 开放中` 的岗位。
- 检查开放岗位是否都存在于本地 JD 库。
- 进入 `推荐牛人 -> 最新`，不再处理 `推荐` 标签。
- 按当前岗位读取可见候选人列表。
- 在列表阶段先批量判断姓名、年龄、学历和本地重复。
- 年龄或学历明确不符合时，不打开在线简历，但仍记为已处理。
- 对需要进一步确认的候选人打开在线简历并完整滑到底，读取候选人的所有简历信息并按照硬性要求去分析。
- 忽略底部的其他名校毕业的牛人、相似候选人信息。
- 根据 HR 提供 JD 的硬性要求分析判断是否合适，缺少直接证据就视为硬性条件未满足。
- 当候选人满足当前岗位的全部硬性要求时，在 BOSS 站内直接转发简历给HR。
- 候选人是否合格都必须记录最小信息，确保后续查重使用。

## 2. 当前 JD 硬性要求库

当前内置岗位：

- 运营负责人
- 海外广告优化师（双休）
- 高级海外广告优化师
- Ui设计师

如果开放岗位里出现 JD 库没有的岗位，小昭应停止该岗位筛选并通知：

```text
jd库里没有xxx岗位的jd，请提供。
```

## 3. 岗位循环和额度

当前执行规则：

- 每个开放岗位在当前轮次累计成功转发 30 份简历给 HR 后切换到下一个岗位。
- 所有开放岗位都达到当前轮次 30 份成功转发后，从第一个岗位重新开始下一轮并重置计数。
- 当前批次为空或暂时没有合格候选人时，继续滚动/加载下一批，不得结束筛选。
- 启动或恢复流程时最多允许刷新一次 BOSS 页面用于同步状态；岗位切换和循环继续不刷新、不重载页面。
- 不再使用本地每日 120 份总额度。
- 岗位切换只看当前轮次成功转发数量是否达到 30；打开简历数量只作查看指标。
- 正常筛选一直运行到时间窗口结束，并先完成当前候选人；用户停止或触发安全停止可提前结束。

## 4. 数据存储

小昭只使用 SQLite 作为本地数据源：

```text
/Users/helloworld/Documents/小昭机器人/.zhipin-copilot/recruitment.sqlite3
```

飞书小昭和 Codex 本地会话必须读取、写入同一份 SQLite。所有飞书查询都必须实时读取这份库，不能使用旧工作区、桌面包副本、`data/.zhipin-copilot`、模型记忆或缓存摘要作为最终数据源。

正常筛选不保存 JSON/JSONL，不保存简历全文。候选人持久化信息只保留：

```text
岗位、姓名、年龄、学历
```

关键表：

- `jobs`：JD 库。
- `job_requirements`：岗位硬性要求。
- `processed_candidates`：全局候选人去重。
- `daily_processed_candidates`：日报/周报按日期统计用的候选人名单。
- `forward_records`：成功转发记录。
- `run_events`：运行事件，如在线简历打开、流程事件等。
- `automation_runs`：自动化运行锁和 heartbeat。
- `reports`：日报、周报、未完成工单日报。
- 去重优先使用姓名、年龄、学历组成的轻量 fingerprint，降低同名候选人误判重复风险。

## 5. 日报和周报

小昭可以生成聚合报表：

- 日报：每天 09:00，统计前一天。
- 周报：每周一 08:00，统计上周一到周日。
- 只读 SQLite，不打开 BOSS。
- 不列候选人名单。
- 不展示代码、路径、命令或内部缓存机制。
- 筛选人数以当前 SQLite 源表交叉校验后的列表读取/处理口径为准，`daily_processed_candidates` 只作补充校验，不能单独作为最终总数。
- 成功转发人数按候选人去重合并 `forward_records.status=SUCCESS`、`processed_candidates.status=forwarded` 和转发成功事件。
- 2.2 可用 `report_metrics.py` 只读生成日报/周报聚合正文，验证数据时不打开 BOSS。
- 日报/周报运行状态会自动带上当天自动化心跳概览。
- 可用 `health-check` 检查 SQLite integrity、关键表、WAL、当天候选人统计和自动化心跳。

## 5.1 数据库备份

小昭支持 SQLite 自动备份：

- 每天 23:10 执行 `boss-7` SQLite 自动备份。
- 使用 SQLite backup API 生成一致性副本，不直接复制运行中的数据库文件。
- 默认同时保存到本机 `data/backups/sqlite/` 和桌面
  `/Users/helloworld/Desktop/小昭机器人2.0/backups/sqlite/`。
- 备份后校验 `integrity_check=ok`，并生成 `.sha256` 和 `.json` 元数据。
- 备份目录禁止放在 Codex/Hermes 配置、技能、缓存或运行目录下。

飞书里也可以查询指定日期报表：

- `@小昭 /日报 2026/06/05`
- `@小昭 今天的日报`
- `@小昭 昨天的日报`
- `@小昭 /周报 2026/06/05`

## 6. 飞书问答

飞书群里使用 `@小昭` 触发。小昭可以回答：

- `@小昭 /help`
- `@小昭 你有什么功能`
- 筛选流程说明。
- JD 硬性要求说明。
- 转发规则说明。
- 自动化任务配置说明。
- 日报/周报格式说明。
- 当前权限边界说明。

普通帮助、问答、报表查询不会创建工单，也不会通知程序负责人。

## 7. JD 库维护

飞书支持维护 JD 库：

- `@小昭 /jd 查看`
- `@小昭 /jd 新增 <岗位名>\n<要求>`
- `@小昭 /jd 更新 <岗位名>\n<要求>`
- `@小昭 /jd 删除 <岗位名>`

JD 命令只能维护 SQLite 中的 JD 和硬性要求，不能变成任意代码、配置、自动化或数据库 schema 修改。
`@小昭 /jd 查看` 必须和 Codex 筛选使用同一份 SQLite JD 数据：通过 `sqlite_store.py jd-library --action 查看` 读取 `.zhipin-copilot/recruitment.sqlite3` 的 `jobs` 和 `job_requirements`。禁止使用飞书缓存、技能说明硬编码、模型记忆或另一份飞书专用 JD 副本回答。

## 8. 自动化流程控制

飞书支持查看和控制自动化流程：

- `@小昭 /自动化流程 查看`
- `@小昭 /自动化流程 修改流程时间 <流程> <HH:MM>`
- `@小昭 /自动化流程 启动 <流程>`
- `@小昭 /自动化流程 停止 <流程>`
- `@小昭 开始 boss-1流程`
- `@小昭 停止 boss-1流程`

启动和停止必须排入真实桌面执行请求，不能只改状态标记。

当前自动化任务：

| `boss-1` | 工作日筛选流程 | 周一到周六 08:00-20:00 |
| `boss-2` | 周日筛选流程 | 周日 19:00-21:00 |
| `boss-3` | 日报 | 每天 09:00 |
| `boss-4` | 周报 | 每周一 08:00 |
| `xiaozhao-unfinished-tickets` | 未完成工单日报 | 每天 09:00 |

## 9. Bug、需求和反馈

小昭可以在飞书记录和查询工单：

- `@小昭 /bug ...`：记录 Bug 单。
- `@小昭 /xq ...`：记录需求单。
- `@小昭 反馈 ...`：记录反馈，并自动生成需求单。
- `@小昭 /bug 查看`：查看所有未完成 Bug 单。
- `@小昭 /xq 查看`：查看所有未完成需求单。
- `@小昭 /bug 1`：查询指定 Bug 单。
- `@小昭 /xq 1`：查询指定需求单。
- `@小昭 /close bug 1`：关闭 Bug 单。
- `@小昭 /close xq 1`：关闭需求单。
- `@小昭 /cp bug 1`：标记 Bug 单完成。
- `@小昭 /cp xq 1`：提交需求单给钟苗验收。

需求单不会直接完成；通过钟苗验收后才变为 `COMPLETED`。不通过则保留在未完成列表。

## 10. 未完成工单日报

每天 09:00，小昭可以汇总未完成需求/Bug：

- 读取 `xiaozhao_feishu_requirement_tickets`。
- 读取 `xiaozhao_feishu_bug_tickets`。
- 排除 `COMPLETED` 和 `CLOSED`。
- 生成未完成工单合并报表。
- 写入 `reports(report_type='unfinished_tickets')`。
- 按配置通过飞书通知程序负责人。

## 11. 安全红线

小昭执行 BOSS 自动化时必须遵守：

- 不主动打开或关闭浏览器、标签页、应用。
- 只使用当前已经打开并登录的 BOSS 页面。
- 禁止点击候选人页的 `打招呼`、`举报`、`不合适`、`收藏`。
- 禁止点击岗位页的 `删除`、`复制`、`保存并发布`、`关闭`。
- 不处理验证码、滑动验证、短信验证、安全验证。
- 页面异常、账号异常、登录异常或 UI 歧义时立即停止。
- 页面健康不能靠某个候选人姓名判断，只能靠核心入口和安全状态判断。

## 12. 当前不再使用的旧功能

以下旧流程已经废弃：

- 旧打分制。
- 60/80 分档。
- 余女士转发。
- 附件简历归档。
- BOSS 页面 JD 抓取作为常规流程。
- JSON/JSONL 落盘归档。
- 把底部其他名校毕业牛人、相似候选人信息当作当前候选人依据。
- 使用 `推荐牛人 -> 推荐` 标签找候选人。
- 本地每日 120 份总额度。

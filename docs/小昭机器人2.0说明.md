# 小昭招聘机器人2.2流程说明

最后更新：2026-06-11

这份文档只记录当前启用的 BOSS/Zhipin 推荐牛人筛选流程。旧的打分制、余女士转发、附件简历归档、BOSS 页面 JD 抓取、JSON/JSONL 落盘归档，都不再使用。

## 1. 核心原则

- 只使用当前已经打开并登录的 BOSS 页面，不主动打开或关闭浏览器、标签页或应用。
- 只处理「推荐牛人 -> 最新」，不再去「推荐牛人 -> 推荐」找候选人。
- 每个开放岗位累计打开 30 份在线简历后切换下一个岗位；所有开放岗位都达到 30 份后，从第一个开放岗位重新开始循环。
- 候选人是否重复，只以 SQLite 本地去重记录为准，不看 BOSS 页面红点。
- 正常流程不落盘 JSON/JSONL，不保存简历全文。
- SQLite 总表 `processed_candidates` 用于全局查重，保留：岗位、姓名、年龄、学历、求职期望/目标岗位、城市、薪资、工作年限。
- 同名或匿名候选人，例如「王先生」，必须结合年龄、学历、期望、当前筛选岗位等字段二次查重，不能只看姓名。
- SQLite 每日名单表 `daily_processed_candidates` 按日期记录当天处理过的候选人姓名，用于日报/周报统计。
- 每 5 个候选人做一次 checkpoint；转发成功、切换岗位、故障、阻断或安全停止时立即 checkpoint。
- 页面是否正常不再看是否出现某个具体姓名，也不靠反复刷新判断。当前 BOSS 页面能看到「职位管理」「推荐牛人」等核心入口，并且没有登录、验证码、滑动验证、短信验证、安全验证或账号异常提示，就按页面正常处理。
- BOSS 出现验证码、滑动验证、短信验证、安全验证、账号异常、页面歧义时立即停止。

## 2. 当前 JD 库

自动流程不再从 BOSS 岗位详情读取 JD，只使用用户提供的硬性要求。

运营负责人：

- 海外中东地区负责经历 1 年以上。
- 语聊或语音房业务。
- 2 年以上海外中东地区运营经验。
- 大专以上。
- 35 岁以下。

海外广告优化师（双休）/ 高级海外广告优化师：

- 海外地区广告优化经验。
- 1 年以上 1v1 社交、直播社交、语聊、语音房、AI 社交产品投放经验，满足其一即可。
- 新增符合条件：a=海外；b=1v1、社交、语音、语聊、直播社交、AI 社交任一关键词。简历全文满足 a+b（分别出现海外和 b 任一关键词，不要求相邻）或 ab（如“海外社交”等连写，同时包含海外和 b 任一关键词）都符合目标产品/业务要求。
- 大专以上。
- 35 岁以下。

Ui设计师：

- 1 年以上直播社交、语聊、语音房、AI 社交 App UI 设计经验，满足其一即可。
- 大专以上。
- 32 岁以下。

如果「职位管理 -> 开放中」出现 JD 库没有的岗位，通过飞书告知钟苗：

```text
jd库里没有xxx岗位的jd，请提供。
```

## 3. 筛选主流程

1. 读取「职位管理 -> 开放中」岗位，并检查这些岗位是否都在用户 JD 库里。
2. 进入「推荐牛人」，选择「最新」标签，并选择当前目标岗位。
3. 在「最新」列表页，先读取当前列表里所有可见候选人。
4. 在列表上批量判断姓名、年龄、学历、求职期望/目标岗位、城市、薪资、工作年限，并先查 SQLite 去重。
5. 年龄或学历明确不符合时，不打开在线简历，只写入岗位、姓名、年龄、学历、求职期望/目标岗位、城市、薪资、工作年限；这些候选人也计入日报/周报筛选人数。
6. 未处理过且列表年龄/学历符合，或列表信息不足时，点击候选人名字打开在线简历。
7. 在线简历打开后，完整滑动到底读取。
8. 打开在线简历后，必须完整滑到底，读取候选人的所有简历信息并按照硬性要求去分析。
9. 忽略底部的「其他名校毕业的牛人」「其他相似经历的牛人」「相似经历」「相似牛人」等其他候选人信息。
10. 使用用户 JD 硬性要求判断候选人。
11. 全部硬性要求满足：BOSS 站内转发给HR。
13. 每天必须记录已处理候选人数和成功转发人数；列表阶段因年龄或学历不符合被跳过的人，也算已处理候选人。

## 4. 判断规则

- 判断标准根据 HR 提供 JD 的硬性要求去分析判断是否合适，缺少直接证据就视为硬性条件未满足。
- 不按关键词硬匹配，要先判断简历里写的是实际产品、投放渠道、分析工具、落地页，还是业务本身。
- Facebook、Instagram、TikTok、Google Ads、Meta Ads、AppLovin、YouTube、小红书、快手、Kwai、巨量、广点通、ASA、Twitter/X 等默认只证明投放渠道经验，不证明投放产品就是社交 App。
- 如果候选人明显更适合另一个开放岗位，可以重新按那个岗位的 JD 判断；只有全部硬性要求满足才转发。

## 5. BOSS 转发规则

- 固定转发给 HR。
- 能看到「HR」时直接点击，不默认输入姓名搜索。
- 合适的候选人直接转发简历给HR。

## 6. 岗位循环与额度

- 当前不再使用全局每日 120 份本地额度。
- 只要在线简历成功打开，就计入当前岗位查看数，不管是否转发。
- 只在「推荐牛人 -> 最新」筛选，不进入「推荐」标签找候选人。
- 每个开放岗位累计打开 30 份在线简历后，不刷新、不重载当前 BOSS 页面，直接切换到下一个开放岗位。
- 所有开放岗位都累计打开 30 份在线简历后，不刷新、不重载当前 BOSS 页面，直接回到第一个开放岗位重新开始同样的 30 份循环。
- 启动或恢复流程时最多允许刷新一次 BOSS 页面用于同步状态；之后本轮流程严禁再次刷新或重载。
- 不使用转发成功数量作为切换岗位条件。
- 一直运行到时间窗口结束、无可处理候选人、用户停止或触发安全停止。

## 7. 飞书通知

普通开始、结束、日报、周报都只发飞书群，不截图，不 @ 钟苗。

- 开始：`现在开始工作`
- 结束：`到点了，下班！`
只有故障或阻断才通知钟苗，并附当前可见 BOSS 页面截图；如果截图失败，要说明失败原因。

- 缺少 JD：`jd库里没有xxx岗位的jd，请提供。`
- 登录或安全异常：`boss登陆异常，请检查～`
- 无法启动：`BOSS筛选任务未正常启动，请检查～`
- 流程故障：

```text
流程故障，故障如下
<具体故障原因、当前步骤、岗位/候选人（如有）、已停止的操作>
```

## 8. 日报与周报

- 日报：每天 09:00 统计前一天，只读 SQLite，不打开 BOSS。
- 周报：每周一 08:00 统计上周一到上周日，只读 SQLite，不打开 BOSS。
- 报告只做聚合统计，不列候选人名单。
- 报告不包含代码、命令、原始路径、内部缓存机制。
- 运行状态不再使用某个具体姓名判断；页面正常以刷新后能看到「职位管理」「推荐牛人」等核心入口为准。
- 报告里的筛选候选人数以当前 SQLite 源表交叉校验后的列表读取/处理口径为准，`daily_processed_candidates` 只作补充校验；不能把在线简历打开数当作筛选总数。
- 报告里的成功转发人数来自 SQLite `forward_records` 中 `status=SUCCESS` 的记录。
- 运行状态不再使用某个具体姓名判断；页面正常以刷新后能看到「职位管理」「推荐牛人」等核心入口为准。
- 报告里的筛选候选人数来自 SQLite `processed_candidates`，不是在线简历打开数。
- 报告里的成功转发人数来自 SQLite `forward_records` 中 `status=SUCCESS` 的记录。
- 列表里年龄或学历不符合、未打开在线简历的候选人，也计入筛选候选人数。
- Token 消耗直接使用本机 Codex 当天 session 总消耗：统计 `~/.codex/sessions/YYYY/MM/DD/*.jsonl` 每个 session 最后一条 `token_count` 的 `total_token_usage.total_tokens` 累计值。

## 9. 飞书问答与工单功能

飞书群里使用 `@小昭` 触发。小昭可以回答只读问题，也可以按权限记录或执行明确命令。

### 9.1 帮助和只读问答

- `@小昭 /help`
- `@小昭 你有什么功能`
- 询问流程、规则、JD 硬性要求、转发规则、日报/周报格式、自动化配置、权限边界。

这些属于普通问答，不创建工单，不通知叶海淋。

### 9.2 报表查询

- 日报：`@小昭 /日报 2026/06/05`、`@小昭 给我2026-06-09的日报`、`@小昭 今天的日报`、`@小昭 昨天的日报`
- 周报：`@小昭 /周报 2026/06/05`

日期格式支持 `YYYY/MM/DD`、`YYYY-MM-DD`、`YYYY.MM.DD`、`YYYY年M月D日`、`今天`、`昨天`。
周报覆盖请求日期所在的完整周一到周日。报表只展示聚合统计，不展示候选人名单、代码、路径或内部缓存机制。

### 9.3 JD 库维护

- `@小昭 /jd 查看`
- `@小昭 /jd 新增 <岗位名>\n<要求>`
- `@小昭 /jd 更新 <岗位名>\n<要求>`
- `@小昭 /jd 删除 <岗位名>`

JD 命令只能维护 SQLite 中的 `jobs`、`job_requirements` 和 `xiaozhao_jd_updates`，不能变成任意代码、schema 或自动化逻辑修改。
`@小昭 /jd 查看` 必须和 Codex 筛选使用同一份 SQLite JD 数据：通过 `sqlite_store.py jd-library --action 查看` 读取 `.zhipin-copilot/recruitment.sqlite3` 的 `jobs` 和 `job_requirements`。禁止使用飞书缓存、技能说明硬编码、模型记忆或另一份飞书专用 JD 副本回答。
小昭先回复 `收到`，执行后再回复结果。

### 9.4 自动化流程控制

- `@小昭 /自动化流程 查看`
- `@小昭 /自动化流程 修改流程时间 <流程> <HH:MM>`
- `@小昭 /自动化流程 启动 <流程>`
- `@小昭 /自动化流程 停止 <流程>`
- 自然语言兼容：`@小昭 开始 boss-1流程`、`@小昭 停止 boss-1流程`

启动/停止必须排入真实桌面执行请求，不能只改一个状态标记。执行前先回复 `收到`，然后返回排队或执行结果。

### 9.5 Bug、需求和反馈

- `@小昭 /bug ...`：记录 HR Bug 单。
- `@小昭 /xq ...`：记录需求单。
- `@小昭 反馈 ...`：记录反馈，同时生成一张需求单。
- `@小昭 /bug 查看`、`@小昭 /xq 查看`：查看所有未完成工单，不限制最近 10 条。
- `@小昭 /bug 1`、`@小昭 /xq 1`：查询指定编号。
- `@小昭 /close bug 1`、`@小昭 /close xq 1`：关闭工单。
- `@小昭 /cp bug 1`：标记 Bug 单完成。
- `@小昭 /cp xq 1`：提交需求单给钟苗验收，不直接完成。

Bug 和需求分别写入 `xiaozhao_feishu_bug_tickets` 与
`xiaozhao_feishu_requirement_tickets`，各自独立编号，展示为 `Bug单 #N` 或 `需求单 #N`。
需求单验收通过后才变为 `COMPLETED`；不通过则为 `ACCEPTANCE_REJECTED`，继续留在未完成列表。

每天 09:00 会发送未完成 xq/bug 合并报表，并写入 `reports(report_type='unfinished_tickets')`。

### 9.6 权限边界

普通飞书用户不能让小昭直接改代码、配置、技能、脚本、自动化定义、数据库 schema 或底层执行逻辑。
这类请求应记录为需求，交由本地 Codex 处理。

`/help` 不能暴露内部角色映射、程序负责人或 HR 用户身份。

## 10. 自动化任务

| ID | 名称 | 时间 | 作用 |
| --- | --- | --- | --- |
| `boss-1` | 工作日流程 | 周一到周六 08:00 启动，持续到 20:00 | 执行完整筛选主流程 |
| `boss-2` | 周末流程 | 仅周日 19:00 启动，持续到 21:00 | 执行完整筛选主流程 |
| `boss-3` | 日报流程 | 每天 09:00 | 统计前一天日报并发飞书群 |
| `boss-4` | 周报流程 | 每周一 08:00 | 统计上周周报并发飞书群 |
| `xiaozhao-unfinished-tickets` | 未完成工单日报 | 每天 09:00 | 汇总未完成需求/Bug 并通知程序负责人 |

## 11. 操作红线

- 禁止点击 `打招呼`、`举报`、`不合适`、`收藏`。
- 禁止点击岗位页的 `删除`、`复制`、`保存并发布`、`关闭`。
- 禁止打开或关闭浏览器、标签页、应用。
- 禁止处理验证码、滑动验证、短信验证、安全验证。
- 禁止在未确认页面位置、页面文字和页面层级一致时点击。
